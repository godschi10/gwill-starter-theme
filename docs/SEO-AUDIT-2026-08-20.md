# SEO AUDIT  -  GWill Starter Theme

**Date:** 2026-08-20 · **Theme version:** v1.3.8 (repo at `/var/www/wp-content/themes/gwill-starter-theme/`)
**Method:** Static analysis of all SEO-related files (inc/seo.php, inc/sitemap.php, inc/social-meta.php, inc/helpers.php), all templates, and all enqueued assets  -  against the 8-section protocol. No live site (the theme is a base template, never directly activated). Verification = `php -l`, grep inventories, cross-file dependency audits, schema review.
**Prior reports:** CONFLICT (v1.3.1), RESPONSIVE (v1.3.2+v1.3.3), CROSS-BROWSER (v1.3.4), SECURITY (v1.3.5), SPEED (v1.3.6), CLEANUP (v1.3.7).

## SECTION 1: CRAWLING & INDEXING

```
[SHOULD] [home, index]  -  home.php + index.php lacked a page H1
[FILE] home.php, index.php, inc/helpers.php
[ISSUE] The blog index (home.php) and the fallback template (index.php) rendered
        post cards (<h2> titles from content.php) with NO page-level <h1>  -  both
        SEO (missing primary heading) and a11y (WCAG 1.3.1) concerns.
[FIX] Added `gwill_index_title()` helper (inc/helpers.php:330-349)  -  returns the
      posts page title when a static front page is set, else the site name. Both
      templates now render `<header class="archive-header"><h1 class="archive-title">
      ...</h1></header>`. (APPLIED  -  v1.3.8.)
```

```
[CLEAN] robots.txt  -  theme-owned, filterable via gwill_robots_txt() (seo.php:467).
        Strips core's wp-sitemap.xml line, advertises the theme's /sitemap.xml,
        sets AI-crawler rules (GPTBot/OAI-SearchBot/ChatGPT-User/ClaudeBot allowed,
        CCBot/Bytespider blocked). Plugin-guarded (gwill_seo_plugin_active()). ✓
[CLEAN] sitemap.xml  -  theme-owned, transient-cached (DAY_IN_SECONDS), busted on
        save_post. Includes posts/pages/public CPTs, excludes hidden slugs.
        Plugin-guarded (v1.3.1). ✓
[CLEAN] Title tags  -  every template type has a unique <title>:
        • Home: "Brand  -  Tagline" (capped at 60 chars, gwill_front_page_title)
        • Singular: "Post Title  -  Brand" (drops brand suffix >65 chars)
        • Archives: "Category Archive  -  Brand" (via WP core + document_title_parts)
        • Search: "Search results for 'X'  -  Brand" (search.php)
        • 404: "Page not found  -  Brand" (404.php)
        No boilerplate duplication. ✓
[CLEAN] Meta description  -  every template type has a distinct description:
        • Singular: excerpt (preferred) or wp_trim_words(content, 30), capped at 160 chars
        • Term archives: term description (trimmed 30 words, 160-cap)
        • Author: "Articles written by X on Site."
        • Home: filterable one-liner (default: "Every guide on Site  -  tutorials…")
        • Contact: filterable one-liner
        • Fallback: site tagline
[CLEAN] Noindex  -  correct targets: search, 404, date, attachment, paged, tag, author
        archives (seo.php:285-286). Categories, front page and singulars index.
        Per-post Yoast-style noindex key respected. Hidden slugs noindexed. ✓
[CLEAN] Canonical tags  -  self-referencing on non-singulars (seo.php:396-429);
        singulars keep core's rel_canonical. Plugin-guarded. ✓
[CLEAN] Pagination  -  paged archives noindexed (modern approach; Google deprecated
        rel next/prev in 2019). No orphan pages detectable (no live content).
```

## Summary

### The single biggest ranking risk
**The missing H1 on the blog index and fallback template**  -  the most important
heading on a listing page was absent, depriving search engines of the primary
relevance signal for the page's content. **Fixed in v1.3.8** with a new helper
+ template header block.

### Prioritized fix order
1. Home/index H1  -  **done** (v1.3.8).
2. Meta description 160-char cap  -  **done** (v1.3.8).
3. Everything else: **CLEAN**.

### Quick wins
- Both fixes are under 10 minutes total (one helper + two template blocks + one mb_strlen guard).
